# MÓDULO 1.2: Infraestructura i18n y Contratos de Tipos de Dominio Musical
# Archivo: tasks/phase-01/1.2-types-i18n.md — Nivel 3 (Micro-tareas Atómicas)

Este módulo establece el catálogo desacoplado de internacionalización (i18n) y los contratos tipados de dominio musical tanto en Frontend (TypeScript estricto) como en Backend (Pydantic).

---

## Micro-tareas

- [x] **1.2.1: Configurar i18next en frontend con catálogos desacoplados (es.json, en.json).**
  - **Archivos:** `frontend/src/i18n/config.ts`, `frontend/src/locales/es.json`, `frontend/src/locales/en.json`, `frontend/src/App.tsx`
  - **BDD:** Given configuración i18n, When se carga la interfaz, Then todas las etiquetas provienen de los catálogos en `locales/` sin cadenas hardcodeadas.
  - **Comando de Test:** `npm --prefix frontend run test`

- [x] **1.2.2: Definir modelos de tipos estrictos de dominio musical en TypeScript.**
  - **Archivos:** `frontend/src/types/music.ts`, `frontend/src/types/scoreConfig.ts`
  - **BDD:** Given modelo de datos de partitura (notas didácticas, solfeo latino, armadura, acordes, digitación y compases), When se compila con `tsc`, Then valida sin errores ni uso de `any`.
  - **Comando de Test:** `npm --prefix frontend run typecheck`

- [>] **1.2.3: Definir esquemas Pydantic en Backend y test de validación cruzada.**
  - **Archivos:** `backend/app/schemas/music.py`, `backend/app/schemas/score_config.py`, `backend/tests/test_schemas.py`
  - **BDD:** Given esquema Pydantic para intercambio API, When se procesa un payload de partitura didáctica, Then valida campos, alturas y serializa limpiamente.
  - **Comando de Test:** `PYTHONPATH=backend backend/.venv/bin/pytest backend/tests/test_schemas.py`
